# Real RawNode trace conformance slice

## Run and claim

```bash
mise run prepare-tla                 # only if the pinned jars are not cached
mise run test-tla-trace              # real Zig executions, TLC, negatives, runner tests
mise run test-tla                    # separate upstream model baseline

# Regenerate only (not a conformance verdict):
mkdir -p .cache/tla
zig build test-tla-trace --summary all
# Validate an existing complete trace, without generating another execution:
PYTHONDONTWRITEBYTECODE=1 python3 formal/trace_check.py .cache/tla/election.ndjson
```

This is a **checked finite implementation-execution slice**, not a proof that
all raftz executions refine Raft. The driver instantiates three real `RawNode`s
and real `MemoryStorage`s; it does not implement another Raft algorithm. No
production source, consensus behavior, logging, or upstream model is changed.
The public-operation boundary was selected after inspecting `Raft.campaign`,
`poll`, `becomeLeader`, `step`, `onPersistEntries`, `RawNode.getReady`,
`advanceAppend`/`advance`, `ReadyProcessor`, the simulation network, and the VOPR
adapter. Existing network tests operate below the required Ready boundary; VOPR
adds WAL/transport machinery outside this slice. A separate, small RawNode driver
keeps persistence and message ownership visible without adding production hooks.

The task does not run by default in `zig build test`: Java and pinned TLA jars are
an explicit opt-in dependency. The dedicated Zig build target always reruns its
two test executions; the mise task performs the actual conformance gate.

## Environment and scope

- Exactly voters `{1,2,3}`, initially empty logs, term/vote/commit zero. Membership
  is seeded through `MemoryStorage.setRaftState`, not synthetic configuration
  log entries. The driver checks both volatile and stored fixed configurations
  at every observation.
- PreVote and check-quorum are explicitly false, priority zero, proposal
  forwarding disabled, unpersisted application limit zero, batching disabled,
  deterministic election seed 42. No scheduler action invokes leader transfer,
  ReadIndex, snapshots, compaction, reconfiguration, or asynchronous persistence.
  The trace header declares this profile; unsupported messages, snapshots,
  snapshot requests, message contexts, priorities, and entry kinds fail closed.
- One globally ordered single-process scheduler. Explicit campaigns replace
  wall-clock timeouts; one explicit local beat generates real heartbeats in the
  conflict scenario. No production timers, threads, RPC or filesystem failures.
- For each Ready, append its entries and set its HardState in MemoryStorage,
  without any intervening delivery or crash. Record that atomic persistence
  completion **before** `advance`. If advance returns a LightReady commit,
  persist that HardState before releasing messages. No crash is scheduled within
  the storage batch. This is not an atomicity claim about multiple storage APIs
  in a concurrent application or about WAL/fsync.
- **All messages, including leader messages that RawNode permits to send early,
  are held until persistence and advance complete.** This conservative legal
  caller schedule does not verify the early-send path, asynchronous Ready,
  ReadyProcessor/Raftor production scheduling, or application callbacks.

## Observation and abstraction

`tests/tla_trace_test.zig` records a snapshot after each campaign, proposal,
message delivery, local beat, getReady, atomic persistence, advance, release,
network drop/duplication and restart. Each snapshot contains all three nodes'
term, vote, role, commit, full log, stored HardState and full stored log, plus
all pending and in-flight messages. Entries include index, term, payload and
context. A proposal includes the actual submitted command independently of its
resulting log entry. An input delivery includes the actual received message.
Ready-owned messages and `Raft.messages` together form the pending bag;
getReady's move between these containers is an abstract stutter.

`formal/trace_check.py` validates the schema and translates observations to a
bounded list of **instructions**, not to fabricated intermediate states.
`RaftzTrace.tla` initializes with upstream `Init`, then executes only the
instruction's named action, bound to the observed node, input message or command.
Every observation becomes a `Matches` checkpoint against model-derived state.
No observed result is assigned to term, vote, log, commit or message variables.
Outgoing requests are inferred from newly observed pending messages, but each
must be generated by upstream `RequestVote`, `AppendEntries` or `Heartbeat` with
exact contents. Responses must already result from upstream `Receive`; the
adapter cannot invent them at checkpoints. Full bags, including multiplicities,
are matched. A delivery must consume a message present in the model network.

| Real boundary / operation | Model action or composition |
| --- | --- |
| Initial RawNode state | Upstream `Init`, then full checkpoint |
| `RawNode.campaign` | `Timeout`, local `SelfVote`, exact outgoing `RequestVote`s |
| `RawNode.step(message)` | `Receive(message)` until consumed; term update and conflicting suffix removal may require multiple upstream actions |
| Vote response elects a leader inside `step` | `Receive`, `BecomeLeader`, `ClientRequest(noop)`, `AdvanceCommitIndex`, observed outgoing requests, checkpoint |
| Proposal | `ClientRequest(actual command)`, observed outgoing appends, checkpoint |
| Leader receives replication acknowledgement | `Receive`, `AdvanceCommitIndex`, observed outgoing requests, checkpoint |
| Local beat | Observed upstream `Heartbeat`s, checkpoint |
| `getReady` | Checkpoint/stutter; message ownership moves but pending bag does not |
| Completed MemoryStorage batch | `PersistState` plus independent full `durableLog` capture, checkpoint |
| `advance` on leader | Local `SelfAck`, `AdvanceCommitIndex`, observed outgoing requests, checkpoint |
| `advance` on follower | Checkpoint/stutter in the observed abstraction |
| Send released Ready/LightReady messages | `SendPendingMessages` guarded by matching durable term/vote/commit/full log |
| Drop / duplicate | Upstream `DropMessage` / `DuplicateMessage` for the exact input |
| Atomic restart | Real RawNode deinit/init with `load_state_on_startup=true`; upstream `Restart`, checkpoint |

`ClientRequest`'s value is an injective record containing command/no-op kind,
hex-encoded UTF-8 payload bytes and context bytes, rather than upstream
Traceetcdraft's constant `0`. Empty application proposals are forbidden by this
driver, so the leader's empty normal entry is unambiguously a no-op. Entry index
is checked for contiguity and represented by sequence position; entry terms and
payload identities are never collapsed. `LogInv` and `LogMatchingInv` therefore
compare actual command identities, including distinct commands in the same term.
The recorded command is its byte value plus context, not an external application
request UUID or a state-machine result.

Append/vote term, source/destination, previous index/term, append entry contents,
commit, vote grant and successful append response index map to the corresponding
upstream fields. Heartbeats use the upstream heartbeat subtype. Rejected append
response index/hint and heartbeat-response index are abstracted as upstream's
zero; these are retry/progress hints, not acknowledged log identity. Raw message
`commit_term`, response `commit`, and rejection hints remain in input evidence
but have no corresponding upstream message field. Any externally visible commit
change still must be justified by model actions. The executions here do not
exercise rejected votes/append requests or vote-based commit propagation.
Stale requests ignored by raftz rather than replied to by upstream are not
adapted: such a mismatch fails, rather than silently dropping the event.

The bag abstraction forgets packet allocation identity and queue container
order, not message multiplicity or the recorded global delivery order. The
scheduler chooses an exact input at each receive. `matchIndex`, votesResponded,
votesGranted and pending configuration index are model-derived auxiliary state,
not directly compared to internal tracker fields. Other unobserved Zig internals
include next/probe/inflight bookkeeping, election clocks/PRNG state, leader ID,
Ready numbers/records, application/applied cursors, uncommitted-byte accounting,
checksums, allocation/refcounts, and storage vtable implementations. This boundary
cannot certify all intermediate Zig instructions inside a public call.

## Explicit local semantic deltas

1. **Synchronous self vote.** Upstream uses a pending self-vote message and a
   Ready boundary; raftz polls itself synchronously during campaign. `SelfVote`
   updates only the candidate's self tally after `Timeout`, with role/vote guards.
   Outgoing votes still cannot be released before durable term/vote. For this
   fixed three-voter slice self vote alone cannot elect a leader. This is a local
   auxiliary-state delta, not a claim that the unmodified upstream action
   sequence directly represents raftz's self-message timing.
2. **Synchronous persisted self match.** raftz updates its own progress in
   `onPersistEntries` during advance rather than sending itself an AppResp.
   `SelfAck` is enabled only for a leader whose full log and term are already
   durable. It updates only self match; commit still uses upstream quorum rules.
3. **Split Ready.** Upstream `Ready` combines `PersistState` and release. The
   wrapper separates them to expose send-before-durability defects and leaves
   all upstream invariants enabled at the intervening model states. A full-log
   `durableLog` variable strengthens the observation over upstream's length-only
   durable state; it is derived from the model log on persistence, never from
   the trace. This detects payload corruption in stored but unchanged-length
   logs. Restart is tested only with all log writes complete; crashes with an
   unpersisted conflicting replacement are not covered by the upstream
   length-only restore action.
4. **Composed synchronous calls.** A winning response can perform election,
   no-op append and sends before `step` returns. A replication acknowledgement
   can commit and broadcast. These are explicit bounded compositions, not an
   unrestricted search over `Next`. Upstream receive may truncate one conflicting
   entry at a time before appending. Only this same input is processed, at most
   36 times (trace logs are capped at 32 entries). Pure `vars'=vars` receive
   stuttering is removed; otherwise upstream's already-satisfied no-conflict
   branch can spin to the microstep limit and create a false deadlock. All
   non-stuttering intermediate states still check all eight invariants.

The local module builds on the pinned etcdraft definitions and attribution in
[`upstream/etcd/tla/etcdraft.tla`](upstream/etcd/tla/etcdraft.tla). Upstream etcdraft
and Traceetcdraft remain byte-for-byte unchanged. Traceetcdraft is not the
validator here: its length-only checkpoints, constant command identity, filtering
of non-trace lines and optional trace truncation do not meet this slice's gate.

## Fail-closed gate and evidence

The parser rejects empty/truncated input, unknown fields/events/features,
duplicate JSON keys, malformed entries, skipped event numbers, unexpected input,
missing initial/end snapshots, missing/inconsistent terminal counts and appended
suffixes. Bounds: 16 MB input, 1,000 observations, 32 entries per log, 4 KiB per
payload/context, 128 messages per observed bag. No record is silently filtered.
These are input-domain limits, **not TLC state constraints that prune mismatches**.

Every checkpoint consumes exactly one observation. TLC deadlock checking remains
enabled. A mismatch has no successor and fails. The microstep bound prevents a
nonterminal loop; only the terminal state has an intentional self-loop. Success
requires exit zero, completed exhaustive exploration of the instruction graph,
zero queued states, and the exact final instruction-count marker. A process
timeout (60 seconds per trace), parser/tool error, missing marker or unfinished
search is never a pass, including when checking negative fixtures. All eight
upstream invariants remain enabled without modification or state constraints:
`LogInv`, `MoreThanOneLeaderInv`, `ElectionSafetyInv`, `LogMatchingInv`,
`QuorumLogInv`, `MoreUpToDateCorrectInv`, `LeaderCompletenessInv`, and
`CommittedIsDurableInv`.

Actual validation with Zig 0.16.0 and pinned TLC tools:

| Real execution | Observations / instructions | TLC generated / distinct states | Result |
| --- | --- | --- | --- |
| Election, duplicate vote request, `alpha`/`beta` commits, atomic follower restart | 129 / 256 | 266 / 265 | Complete; all nodes commit index 3 |
| Partition/loss, old leader's uncommitted `orphan`, term-2 leader, `replacement`, conflicting suffix repair, `healed` | 219 / 441 | 457 / 456 | Complete; all nodes commit index 5 |

Together: three elections, six application proposals (five survive), 76 message
deliveries, four drops, one duplication, one restart, one explicit heartbeat
broadcast. The conflict scenario overwrites index 3's term-1 `orphan` with the
term-2 leader no-op, retains committed `shared`, then converges on `replacement`
and `healed`. Both test functions assert the final real commit indices; the
conflict test additionally checks stored payloads on every node.

Nine schema-valid mutations reach TLC and are rejected by a blocked semantic
transition/checkpoint: term, vote, committed payload, same-term committed command
identity substitution, durable payload, release-before-persist,
leader-ack-before-persist, missing proposal operation (renumbered with a valid
terminal), and message causality. Five structural negatives cover empty input,
partial last line, missing terminal, unsupported event and appended suffix.
Negatives are generated from the current real execution, not accepted/rejected
by filename or hash. Seventeen focused adapter/runner tests plus ten existing
runner tests pass. `mise run test` passes 789/789 default Zig tests separately;
the trace build passes 2/2 additional Zig tests. `mise run fmt-check`,
`git diff --check`, and upstream checksums pass. The upstream `test-tla` baseline
also passes: 34,573 generated / 4,650 distinct single-node states, and 100 sampled
three-node traces / 10,769 states. The three-node baseline is still simulation,
not exhaustive Raft verification.

Artifacts are retained beneath `.cache/tla/`: `election.ndjson`,
`conflict.ndjson`, `mutations-*/`, and `runs/trace-*/` containing the exact input,
expanded `steps.ndjson`, model/config copies, `command.json`, `tlc.log`, state
files and any TLC counterexample. On Zig scenario failure, best-effort partial
`election.failed.ndjson` / `conflict.failed.ndjson` evidence has no valid terminal
and cannot pass. These files and MemoryStorage snapshots in them are durable
**diagnostic files**, not WAL persistence evidence. Runs print their unique
artifact paths and are never deleted by the runner.

Remaining gaps include exhaustive schedule exploration, denied/stale elections,
rejection-hint optimizations, early sends, asynchronous/interleaved Ready,
crashes between persistence operations, WAL recovery/partial writes, application
semantics and liveness, non-UTF-8 payloads, membership changes, PreVote,
check-quorum, transfer, reads, snapshots/compaction, multi-Raft and real transport.
A passing bounded trace does not establish any of those properties.
